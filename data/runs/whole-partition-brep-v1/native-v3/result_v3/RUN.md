# 公共边界与过渡区光顺改进

本轮保留原 GUI 的 359 个分区，针对锯齿边界、牌面拐角和窄过渡区重新优化公共曲线与区域支撑面。交付 STEP 为 **902 面**，上一版为 989 面，参考件为 2739 面。最终文件已在本机 Creo 11 安装自带毫米配置下实际形成 **1 个闭合活动实体、0 个体外游离曲面**，灰色显示已查看。拟合只使用原 STL 和固定标签，没有调用 Geomagic 或读取参考 CAD 曲面。

牌面及多数过渡区域的褶皱明显减轻，八个复核分区的法向误差 P95 均下降。**78 区下缘仍有局部可见波纹，整体接缝法向统计也未全面改善，因此本版是有实测改善的交付样件，尚不代表全区域光顺或任意模型的通用验收通过。**

**接缝间距 P95 和全部接缝法向 P95 没有改善。** 接缝法向统计包含设计锐边，且两版内部拟合域不同；这些数值仍按原协议完整保留，不能仅凭内部曲线 C2 宣称所有相邻面达到 G1。最大 STEP 边公差为 0.003661 mm，仍低于固定的 0.005 mm 上限。GEOM_CHECKS 的 1 表示仍有一个导入特征被标记，不是一个活动实体失败。

## 算法与边界对应

先对公共三次曲线求最小弯曲解：沿源表面的移动上限 0.12 mm，离开两侧源三角形平面的上限 0.003 mm。交汇点由邻面共用；实际连续交点检查拒绝过冲和微小回环。本版 2451 条公共曲线均为内部 C2，2227 条采用最小弯曲求解，213 条采用拓扑保护的正系数曲线，11 条采用求解回退的正系数曲线；没有折线回退。

区域支撑面采用带位置约束的二次规划，拟合原 STL 的点和锐边分离法向，并最小化物理尺度下的弯曲项。新增节点区间内部探针和源边中点检查，防止只在顶点、重心拟合成功却在中间鼓包。连续公共曲线到支撑面的最大残差为 0.001994 mm。

相邻小域若出现源 STL 没有的剧烈法向跳变，再尝试局部共用支撑面，保留每个原分区各自的裁剪边界和三角形归属。最终采用 25 组相邻域的共用支撑面，组内接缝位于同一张 C2 曲面上；没有把整件放入一个拟合系统。邻区变差、源锐边、非单值投影或误差超限的方案被拒绝。[区域归属与表达成本](metrics/representation.json)及[精确三角形映射](metrics/chart_layout.npz)验证了 491132 个源三角形各被覆盖一次。

独立 Creo 诊断发现过局部开口。单独重新平滑对应边界仍失败；共享支撑面修复后才实际得到闭合活动实体。诊断 CAD 仅用于定位，不提供拟合几何。[失败导出的自由边记录](metrics/rejected_creo_free_edges.json)和实验对照均保留。

早期 v10 的独立反向最大误差为 0.0792 mm，被排除；v11 消除了该超限，但实际 Creo 仍未形成活动实体。旧记录的状态字样按原值保留，不能把其中的 `DiagnosticOnly` 当作验收通过。现在统一入口对距离超限和 Creo 非实体结果都明确记录失败。

另一个追加修复候选 v15 也通过了 Creo，但 197 区出现了新的窄带波纹，故最后选择 v14。这个例子说明 P95 和拓扑通过仍不足以代替可见质量审查。[未采纳追加修复对比](metrics/rejected_local_repair.png)中，中列为采用的 v14，右列为未采用的 v15；该图自己的“上一版／本版”标题指这两次试验，不是本文主对照的 989 面版。

## 配置比较与时间

本轮实际比较了正系数边界、最小弯曲边界、有界支撑、两档更强公平项、放宽源平面预算、不同边界法向罚项和局部共用支撑面。放宽源平面预算到 0.009 mm、增大公平项到 1e-5/1e-4、直接施加全边界法向罚项，均未取得整体更好的局部结果；例如 78 区的 P95 分别升到 28.54°、16.78°、22.27°和 18.39°，因此没有选用。

这些是有缓存、布局会变化的探索对照，不是严格单变量实验。四区公平项 1e-5 和 1e-4 的运行分别为 263.38 s、365.62 s；原有界正系数边界四区试验为 179.24 s。详细配置、各区域结果及失败保存在 `metrics/experiments.json`，不能把不同缓存条件的耗时直接解释为算法加速比。

最终使用 8 个拟合进程；自动相邻域修复使用 6 个进程，各进程 BLAS/OMP 均为 1。最后一轮复用 902 张已验证支撑面，边界及缓存复验 65.70 s、原生装配 144.32 s、STEP 导出与回读 206.18 s、独立几何检查 149.80 s、全部区域导出 64.91 s，包含 Creo 验证与截图的工作流共 878.77 s。采用的局部共用支撑先导和自动修复分别另耗时约 41.42 s、316.10 s；未采用的补充修复另耗时 157.85 s。这些时间有其他诊断并行运行，**不是完整冷启动性能基准**。

使用方法见 [工具说明](../../../../../tools/mesh_brep/README.md)。统一入口新增 `--repair-smooth-joins`，也保留独立局部修复入口。参数记录、原 STL 对应固定分区和三角形映射保留；中间拟合缓存清理后，不能用已删除的续算路径精确回放本交付。新输入可从固定分区重新运行，但没有把本次缓存结果冒充所有输入或冷启动都通过。

## 验证与整理

Python 回归 **66 项通过，0 失败，0 跳过**，见 [测试日志](metrics/tests.log)。真实运行另覆盖微小自交、内插鼓包、共用支撑面、固定区域覆盖、完整 STEP 和 Creo 原生体。复杂分区在源顶点处相接时，对比图现在直接绘制全部源边界段，已用 197、200 区实际重跑。C++ 产品与 GUI 未改，仍保持 `DiagnosticOnly / can_apply=false`。

本目录只保留整件、分区件、Creo 原生证据、必要指标及对比图。本轮中间试验在提取指标后移入 Windows 回收站；上一轮已发布的 `native-v2/result_v2` 作为对照保留，原 STL、参考 STEP 和其他工作树未动。原始指标中的旧绝对路径只记录来源，当前可打开文件以本说明及 `run.json` 的相对路径为准。

本轮主要方法实现使用本仓库数值代码与 OCCT；有界二次规划的求解接口参考 [OSQP 官方文档](https://osqp.org/docs/solver/index.html)。其他模型尚未使用本版逐一复验，全模型 G1、窄角残余波纹和跨 CAD 几何检查仍是后续验收项。
